## 検索品質の実測サマリ（20〜30クエリ、実データ3510語）

大半のクエリ（かな入力・カタカナ入力・英字入力・長音違い・タイプミス）は目的の語を上位（0〜2位）で正しく返した。例: `api`→API(1位)、`さーばー`（長音付加ミス）→サーバ(1位)、`tcp/pi`（タイプミス）→TCP/IP(1位)、`るーてぃんぐ`→ルーティング(1位)、`ねっとわーく`→ネットワーク(1位)。

明確に問題があったのは以下:
- **`三層`（漢数字）→ 0件**（上記[1]、要件が明示する例そのものが破綻）
- `十進数`/`二進数`（漢数字）→ 目的語（`10進数`/`2進数`）は取得できるが1位ではなく3位（`2進数`が先に出る。誤りではないが要件の「1文字差はスコアで自然に上位に来る」という主張ほど強くは効いていない）
- `しーくえる`（SQLの非代表的な読み）→ 0件に近い無関係な結果（「シーク時間」等）。ただしこれは要件定義書`docs/requirements.md:135`が「非代表的な読みは英字で直接引く」ことを明示的な設計としているため、`sql`と英字で引けば正しく1位に出ることを確認済み。**バグではなく設計通りの挙動**と判断した。
