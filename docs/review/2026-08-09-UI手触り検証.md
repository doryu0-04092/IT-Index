## 3. 行った修正

### コミット1: `fix: 品質ゲートがビルド成果物と使い捨て調査specに埋もれる問題を直す`

- `eslint.config.js` — `android/app/build/**`, `android/app/src/main/assets/**`,
  `dist-electron/**`, `release/**`, `test-results/**` を除外に追加
- `playwright.config.ts` — `testIgnore: ['**/investigate-*/**']` を追加

**効果（実測）**: lint **16677件 → 24件**（実コードのみ）。e2e は恒久ゲートだけを走る状態に戻った。

### コミット2: `feat: 検索をキーボードだけで完結できるようにし、0件時の無反応を解消する`

- `src/ui/pc/SearchScreen.tsx` — combobox パターンを実装
  - `role="combobox"` / `aria-expanded` / `aria-controls` / `aria-activedescendant` / `aria-autocomplete="list"`
  - 結果一覧に `role="listbox"`、各行に `role="option"` と `aria-selected`
  - ↓↑で選択、Enterで表示、Escapeで選択解除（2度目で入力クリア）
  - マウスホバーでも選択位置が同期する（キーボードとマウスで表示が食い違わないように）
  - 選択行を `scrollIntoView({block:'nearest'})` で画面内に保つ
- `src/index.css` — 選択行のスタイル（`.search-result-active`。hoverより濃く、左に線）
- `src/ui/shared/activeIndex.ts` / `.test.ts` — 選択位置の折り返し計算を純関数として切り出し、**単体テスト8件を追加**

**設計判断**: フォーカスを結果側へ移す方式（roving focus）は採らなかった。
移すと**絞り込みの続きが打てなくなる**ため、フォーカスは入力欄に残し
`aria-activedescendant` で選択位置だけを伝える形にした。

**a11y の例外**: 検索欄の `autoFocus` は `jsx-a11y/no-autofocus` に触れるが、
**この画面はアプリの入口そのもの**で、起動のたびに入力欄を押させるのは手触りを損なう。
理由をコメントに書いた上で1行だけ抑制した（無条件の抑制はしていない）。

## 5. 直さずに残したもの（判断と理由）

**「良くなるかもしれない」だけでは動かない**という規範に従い、
根拠が薄いもの・仕様判断が要るものは手を付けず、ここに残す。

| 項目 | 残した理由 |
|---|---|
| **lint 23件**（`set-state-in-effect` 6件 / `exhaustive-deps` 5件 / 未使用変数2件 / `no-autofocus` 2件 / e2e調査spec由来 8件） | `set-state-in-effect` は「効果内の同期setStateが連鎖レンダを生む」という**性能上の警告**で、直すには状態の持ち方の再設計が要る。**利用者に見える不具合の証拠が無い**段階で6ファイルに手を入れるのは割に合わない |
| **④ ホームの空白** | 「最近見た語」「弱点の可視化」等は**機能追加**であり、要件（`docs/requirements.md`）の範囲判断が要る。指示なしに製品の形を決めるべきでない |
| **⑤ 検索の雑音** | `docs/requirements.md §5.1` が定めたスコアリング（2-gram Dice + 一致加点）そのものの変更にあたる。閾値を上げると**表記ゆれの吸収**という本来の狙いを損なう恐れがあり、実データでの評価なしに変えるべきでない |
| **investigate-* の削除** | ファイル自身が「削除してよい」と宣言しており削除が妥当だが、**削除は取り消しにくい操作**のため実行しない（除外設定で無害化するに留めた）。本人の判断で削除を推奨 |
| **Android版UIのキーボード対応** | Androidは touch 前提のため、キーボード操作の優先度が低い。PC版のみに絞った |
