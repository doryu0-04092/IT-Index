# データベース — 参考情報（fe-siken.com主軸）

出典: fe-siken.com カテゴリ9（データベース）9-1（データベース方式）・9-2（データベース設計）・9-3（データ操作）・9-4（トランザクション処理）・9-5（データベース応用）。突き合わせは terms.json 用語リスト（225語、ファイル記載順）に対して行った。全角半角・記号・ハイフンの表記ゆれのみ同一語とみなし、語形が異なる類義語（例:「NULL」と「ヌル」、「参照制約」と「参照整合性制約」）は別語として扱い、下の「見つからなかった語」側に近縁情報として記載した。

- **2相コミットメント**: データベースシステムにおいて、トランザクションの一貫性を保証するための手法であり、分散システムで複数のデータベースにまたがるトランザクションを処理する際に用いられる。準備段階でのトランザクション準備確認とコミット段階での変更確定により、データの整合性を保つ。
- **ACID特性**: データベースにおけるトランザクション管理の基本的な特性であり、原子性（Atomicity）、整合性（Consistency）、独立性（Isolation）、耐久性（Durability）の頭文字を取ったもの。これらの特性によりデータベースシステムは信頼性を高め、正確なデータの管理を実現する。
- **B-treeインデックス**: データベースにおいてデータの検索を効率化するためのデータ構造であり、特に大量のデータを扱う際に検索速度を向上させる。データが常に整然と整理されており、特定の条件に基づいてデータを迅速に検索できる。
- **DDL**: データベースにおいてデータの構造を定義、変更、削除するための言語である。テーブルやビューなどのデータベースオブジェクトの作成や削除、フィールドの設定を行う際に使用される。
- **DML**: データベースにおけるデータの操作を行うための言語である。この言語を使用することで、データの挿入、更新、削除、検索などの操作を簡単に実行できる。
- **ELT**: データを抽出（Extract）し、ロード（Load）した後に変換（Transform）するプロセスのことである。データがさまざまなソースから集められ、データベースやデータウェアハウスに保存された後、分析や利用のために整えられる流れを指す。
- **ETL**: データベースにおけるデータ移行のプロセスの一つで、データを抽出し、変換し、ロードする手順を指す。異なるデータソースから情報を集め、目的のデータベースに整理して格納する役割を持つ。
- **HDB**: 異なるデータモデルを統合して管理するハイブリッドデータベースであり、リレーショナルデータベースと非リレーショナルデータベースの両方の特性を活かして柔軟なデータ管理が可能になる。
- **IRDS**: データ資源を体系的に管理するための情報資源辞書システムである。データの定義や分類、関連性を明確にすることで、情報の利用効率を向上させる役割を果たす。
- **NDB**: データをグラフ構造で管理するネットワークデータベースであり、データがノードとエッジで表現され、複雑な関係を柔軟に扱えるのが特徴である。
- **NULL**: データベースにおいて「無」とか「値が存在しない」という状態を表す特殊な値である。
- **OLTP**: リアルタイムでデータの処理と管理を行うシステムのことである。主に銀行や通販サイトなど、顧客が直接操作する場面で用いられ、迅速かつ正確な取引を支援するために設計されている。
- **OODB**: データをオブジェクトとして管理するオブジェクト指向データベースであり、データとその動作を一緒に扱うことができ、複雑なデータ構造やリレーションシップを自然に表現することが可能である。
- **RDB**: データを表形式で管理するリレーショナル・データベースであり、各データは行と列で構成されたテーブルに格納され、関連するデータを効率的に管理できる。
- **SELECT文**: データベースから特定の情報を取得するためのSQL文の一つである。テーブルから必要なデータを選び出し、条件を指定して絞り込むことができる。
- **SQL**: データベースと対話するために使用されるプログラミング言語である。主にデータの取得、追加、更新、削除などの操作を行うために用いられ、リレーショナルデータベースの構築や管理に欠かせない存在である。
- **XMLデータベース**: XML形式でデータを保存・管理するためのデータベースであり、階層構造でデータを扱うため、複雑なデータを自然に表現できる特性を持つ。
- **一意性制約**: データベースにおいて、特定の列の値が全ての行で異なることを保証するルールである（9-3では「特定の列が持つ値が、テーブル内のどの行でも一度しか使われないことを保証するためのルール」とも説明）。
- **エンティティ**: データベースにおいて独立した存在を表す概念である。情報を管理する対象となる物や事柄を示し、例えば「顧客」や「商品」などが該当する。
- **カーソル**: データベースにおいてSQLクエリの結果セットを操作するためのオブジェクトである。カーソルを使用することで、クエリの結果を一行ずつ取り出して処理しやすくなる。
- **カーディナリティ**: データベースにおけるテーブル同士の関係性を表す概念である。一つのテーブルのレコードが他のテーブルのレコードとどのように関連しているかを示す。
- **概念スキーマ**: データベースの3層スキーマアーキテクチャにおける中間層の一部であり、データベースの全体的な構造や関係を定義するものである。
- **概念データモデル**: データベースの設計において、情報の構造や関係を図示するための抽象的なモデルである。
- **外部キー**: データベースにおいて、他のテーブルの主キーを参照するためのフィールドである。
- **外部スキーマ**: データベースの3層スキーマアーキテクチャにおける層の一つであり、ユーザーがデータベースにアクセスするための視点を提供する仕組みである。
- **関係**: データベースにおける関係モデルにおいて、データのセットを表す構造の一つであり、表形式のデータを扱い、行と列で構成されている。
- **関係演算**: データベースにおけるデータ操作の基礎となる手法の総称である。選択は特定の条件を満たすレコードを取得し、射影は必要な列だけを取り出す操作である。
- **関係モデル**: データベースにおけるデータの構造を定義するための方法の一つであり、データはテーブル形式で整理され、各テーブルは行と列から構成される。
- **完全関数従属**: データベースにおいて、ある属性が他の属性に完全に依存している状態を指す。
- **共有ロック**: データベースにおける同時実行制御の一種であり、複数のトランザクションが同時に特定のリソースを読み取ることを許可する制御機構である。このロックを持つトランザクションはそのデータを変更することはできないが、他のトランザクションも同様にそのデータを読み取ることが可能である。
- **検査制約**: データベースにおけるデータの整合性を保つために定義されるルールのことを指す。テーブルに格納されるデータが特定の条件を満たすことを要求するものである。
- **構造型データベース**: データを特定の形式や構造に従って保存するデータベースの一種であり、データは表形式で管理され、各列が特定の属性を示し、各行が個別のレコードを表す。
- **構造化データ**: 特定の形式に従って整理されたデータであり、比較的容易に分析や処理ができるタイプの情報を指す。データベースの表形式で保存されているものや、スプレッドシートのような構造を持つデータがこれに該当する。
- **コミットメント制御**: 特に分散データベースにおいて、トランザクションが正しく処理されることを保証するための仕組みである。異なるデータベースが関与する場合でも、一貫性を保ちながらトランザクションを管理する役割を果たす。
- **削除権限**: システムやアプリケーションにおいて、特定のユーザーまたはグループがデータを削除することを許可される権限であり、この権限を持つ者は自分に許可されたデータを自由に消去できる。
- **参照権限**: 情報システムにおいて特定のデータやリソースにアクセスするための許可を示すものであり、この権限を持つユーザーは必要なデータを閲覧したり読み取ったりすることができるが、変更や削除といった操作は行えない。
- **参照制約**: データベースにおける整合性を保つためのルールであり、あるデータが他のデータと正しく関連していることを保証するための制約である。子テーブルのデータは親テーブルに存在するデータにのみ依存するように制限される。
- **実表**: データベースに実際に存在するデータを格納するための表のことである。データモデリングによって設計された論理モデルを基にして作られ、実際にデータが入力される場となる。
- **集合演算**: 複数の集合に対して行う操作のことを指す。特に、和（Union）、差（Difference）、積（Intersection）の三つの基本的な演算がある。
- **集約関数**: データベースにおいて、複数の行のデータをまとめて一つの値に変換するための関数である。合計を求めるSUM、平均を算出するAVG、最大値を求めるMAX、最小値を求めるMINなどが含まれる。
- **主キー**: データベースにおいて各レコードを一意に識別するための属性や項目である。
- **推移関数従属**: データベースにおける正規化の概念の一つで、ある属性が他の属性に依存している関係を示すものである。
- **ストリーミングデータ**: リアルタイムで生成されるデータの流れを指し、継続的に送信される情報のことを言う。センサーからのデータ、オンラインの取引情報、ソーシャルメディアの投稿などが含まれる。
- **相関名**: SQLのデータ操作言語において、特定のテーブルや列に対して別名を付けるための識別子である。これにより、クエリがより明瞭になり、複雑な問い合わせでも理解しやすくなる。
- **挿入権限**: データベースや情報システムにおいて新しいデータを追加するための権利であり、この権限を持つユーザーは既存のデータに影響を与えない形で情報を挿入できる。
- **属性**: データベースにおいて、エンティティ（実体）を構成する特性や性質を示す要素である。
- **第1正規化／第1正規形**: データベースにおける正規化の最初の段階を指す概念である。テーブル内のすべてのデータが原子性を持つこと、つまり各フィールドが単一の値を持つ必要がある（fe-siken見出しは「第1正規形」）。
- **第2正規化／第2正規形**: データベース設計において、テーブルの構造を整理し、冗長性を減少させるための基準の一つ（fe-siken見出しは「第2正規形」）。
- **第3正規化／第3正規形**: データベース設計において、データの冗長性を排除し、整合性を高めるためのルールの一つ（fe-siken見出しは「第3正規形」）。
- **チェックポイント**: システムやアプリケーションの状態を保存する機能であり、特に障害回復の場面で重要な役割を果たす。特定の時点での情報を記録することで、トラブルが発生した際にその記録から復旧を可能にする。
- **定義域**: 関係モデルにおいて、特定の属性が持つことができる値の集合を指す。
- **データウェアハウス**: 企業や組織が大量のデータを蓄積し、分析するための特別なデータベースのことである。異なるデータソースから情報をまとめ、一元管理することができるため、経営判断やマーケティング分析に役立つ。
- **データ機密保護機能**: データベース管理システムにおいて、データの機密性を確保するための機能である。
- **データクレンジング**: データの誤りや不正確な情報を修正し、データの質を向上させるプロセスである。
- **データディクショナリ**: データベース内のデータやその意味、構造、関係性に関する情報を管理するための辞書のことを指す。テーブル名、カラム名、データ型、制約条件などが記載されている。
- **データベース制御機能**: データベース管理システムにおけるデータの管理や操作を支援する機能のことを指す。
- **データベース操作機能**: データベース管理システムにおいてデータの作成、読み取り、更新、削除を行うための基本的な機能である。
- **データベース定義機能**: データベース管理システムにおいて、データベースの構造やスキーマを定義・変更するための機能である。
- **データマート**: 特定のビジネス部門やプロジェクトのために設計された小規模なデータウェアハウスのことである。大量のデータを整理し、分析しやすい形にする役割を果たす。
- **データレイク**: 大量のデータをそのまま格納するためのストレージ環境である。データの形式を問わず、構造化データや非構造化データを一括して保存できる特徴がある。
- **デッドロック**: コンピュータシステムにおいて、複数のプロセスが互いにリソースを占有し、相手が解放するのを待ち続ける状態のことを指す。
- **転置インデックス**: データベースにおいて検索性能を向上させるための技術であり、通常のインデックスが行を基準にデータを整理するのに対して、転置インデックスは列を基準にデータを整理し、特定の列に基づく検索を迅速に行えるようにする。
- **透過性**: 主に分散データベースにおいて、システムの複雑さを隠し、ユーザーがその背後の処理を意識せずにデータを利用できる特性である。
- **ドキュメント指向データベース**: データをドキュメント形式で管理するデータベースの一種であり、各データが自己完結した情報の塊として保存され、JSONやXMLといった構造化されたフォーマットで記述される。
- **内部スキーマ**: データベースの構造を定義するためのスキーマの一つであり、データがどのように物理的に格納されるかを示している。
- **ハッシュインデックス**: データベースでデータを効率的に検索するために使用されるインデックス構造の一つであり、ハッシュ関数を使用してデータを格納することで、特定のキーに関連付けられた値を迅速に見つけることができる。
- **半構造化データ**: データの一部に構造があるが、それが完全には定義されていない形式のデータである。XMLやJSON形式のデータが代表的な例であり、タグやキーの対を使用して情報を整理している一方で、全ての属性が同一である必要はない。
- **非NULL制約**: データベースにおいて特定のフィールドに値が必ず存在することを保証する制約である。
- **非構造化データ**: 特定の形式や構造を持たないデータである。テキスト文書、画像、音声、動画など、多種多様な形で存在する。
- **ビッグデータ**: 従来のデータ処理手法では扱いきれないほどの大規模なデータセットを指す。データの量、速度、多様性が非常に大きく、テキスト、画像、動画などさまざまな形式で存在する。
- **フィールド**: データベースにおいて、特定のデータを格納するための項目を指す。データベースの表における列のことで、それぞれのフィールドは特定の情報の種類を持つ。
- **物理データモデル**: データベース設計の一環として、実際のデータの格納方法や構造を詳細に記述したものである。
- **部分関数従属**: データベース設計における正規化の概念の一つで、ある属性が部分的に主キーに依存している状態を指す。
- **分散データベース**: データが複数のコンピュータやサーバに分散して保存されるデータベースのことであり、各サーバが独立してデータを管理し、必要に応じて相互に通信してデータを取得する。
- **保全機能**: データベースにおける情報の整合性と持続性を確保するための機能である。
- **メタデータ**: データを補足する情報のことである。データの内容、形式、構造、作成日時、作成者などの情報を指す。
- **リレーションシップ**: データベースにおいて異なるテーブルやエンティティ間の関連性を示す概念である。
- **レコード**: データベースにおける情報の単位であり、特定のエンティティに関する属性（情報）の集まりを指す。テーブルにおける1行のことを指す。
- **レプリケーション**: 分散データベースにおいて、データの複製を作成し、複数のデータベースノード間でその複製を同期させるプロセスである。データの冗長性を確保し、可用性を向上させる目的で使用される。
- **ロールバック**: システムやデータベースにおいて、何らかのエラーや障害が発生した際に、以前の正常な状態に戻す手法であり、バックワードリカバリとも呼ばれる。
- **ロールフォワード**: データベース管理において、システム障害からの復旧手法の一つであり、フォワードリカバリとも呼ばれ、最新のバックアップデータを用いながら、その後の変更履歴を適用してシステムを以前の状態に戻す方法である。
- **ロック粒度**: データベースや同時実行制御において、データに対してロックをかける単位の大きさを指す。行レベル、ページレベル、テーブルレベルなど、異なる粒度が存在する。
- **論理データモデル**: データの構造や関係を抽象的に表現する手法であり、データベースの設計において重要な役割を果たす。
