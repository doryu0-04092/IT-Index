# ソフトウェア — 参考情報（fe-siken.com主軸）

出典: fe-siken.com カテゴリ5（ソフトウェア）5-1〜5-5。突き合わせは terms.json 用語リスト（175語、ファイル記載順）に対して行った。全角半角・記号・ハイフンの表記ゆれのみ同一語とみなし、語形が異なる類義語（例:「原始プログラム」と「ソースプログラム」）は別語として扱い、下の「見つからなかった語」側に近縁情報として記載した。

- **API**: 異なるソフトウェアやサービスが互いに通信し、機能を利用し合うための接続方法を示すもの。あるプログラムが別のプログラムの機能を呼び出し、データを取得したり操作したりする手段を提供する。
- **CORBA**: 異なるシステム間でオブジェクトを利用するための標準的な技術。さまざまなプログラミング言語やプラットフォームで作成されたアプリケーション同士が相互に通信し、データをやり取りすることが可能となる。
- **DLL**: ソフトウェアが共有の機能を利用できるように作られたファイル。DLLファイルには、プログラムが動作するために必要な関数やデータが含まれており、複数のアプリケーションが同時に使用できる。／ 補足(saycon): Dynamic Link Library — プログラムの実行中に呼び出される共有ライブラリ。
- **FATファイルシステム**: ファイルを保存するためのデータ構造で、主にディスクやUSBメモリなどで使用される仕組み。ファイルの位置情報を管理するためのテーブルであり、各ファイルがどのセクタに保存されているかを記録する。
- **IDE**: プログラミングを行うための統合開発環境。プログラムを書くためのエディタ、コードのチェックや補完、デバッグ機能、さらにはコンパイラやビルドツールなどが一つのソフトウェアに組み込まれている。／ 補足(saycon): プログラムの開発、デバッグ、テストを統合的に行えるツール。
- **LRU**: 最近最も使用されなかったページを対象にした仮想記憶管理の手法。／ 補足(marke-predict): 実記憶装置上のページのうち参照されない経過時間が最も長いページを追い出す方法。
- **NTFS**: マイクロソフトが開発したファイルシステムの一つで、主にWindowsで使用される。ファイルのセキュリティを強化するためのアクセス制御機能を提供し、ユーザーやグループごとに権限を設定できる。
- **OS**: コンピュータやスマートフォンなどのデバイスを動かすための基本的なソフトウェア。ハードウェアとアプリケーションソフトウェアの間で橋渡しを行い、ユーザーがデバイスを使いやすくするための環境を提供する。／ 補足(saycon): コンピュータハードウェアを管理し、他のソフトウェアが動作するための基盤を提供するソフトウェア。
- **OSGi**: オープンサービスゲートウェイイニシアティブの略で、Javaプラットフォームでのコンポーネント管理技術。ソフトウェアを複数の小さなモジュールに分割して管理でき、プログラムの柔軟性や再利用性が向上する。
- **UNIX**: 1970年代に開発されたオペレーティングシステムの一種。多ユーザー、多タスクをサポートしており、同時に複数のユーザーが利用できる環境を提供することが特徴。
- **アセンブラ**: アセンブリ言語を機械語に変換するツール。アセンブリ言語は、コンピュータのハードウェアに近い低水準なプログラミング言語で、人間が理解しやすい形で命令を記述できる。
- **インタプリタ**: 高級プログラミング言語を直接実行するためのソフトウェア。プログラムコードを逐次読み込んで解釈し、その都度実行する方式のため、デバッグが容易で迅速な検証が可能。
- **オーバーレイ方式**: コンピュータのメモリ管理手法の一つで、実行中のプログラムが必要とする部分だけをメモリに読み込む方式。
- **オープンソースソフトウェア**（＝OSS 20 も同一概念）: ソフトウェアのソースコードが公開されており、誰もが自由に使用、改良、配布できることを特徴とする。LinuxやApache HTTP Serverが代表例。／ 補足(marke-predict): ソースコードの公開を前提にソフトウェアの改良・再配布が誰でも無償で行えるソフトウェア。
- **オブジェクトライブラリ**: プログラム開発において再利用可能な部品やコンポーネントを集めたもの。開発者は新たにコードを書くことなく、既存のオブジェクトを使って迅速にアプリケーションを構築できる。
- **カーネルモード**: オペレーティングシステムがハードウェアに直接アクセスできる特別な動作モード。このモードでは、CPUがすべての命令を実行できる。
- **ガーベジコレクション**: プログラムが使用しなくなったメモリ領域を自動的に解放する技術。
- **カレントディレクトリ**: 現在操作を行っているフォルダのこと。コンピュータ上でファイルを管理する際に、どの位置で作業を行っているかを示す重要な概念。
- **クロスコンパイラ**: 一つのプラットフォーム上で動作し、異なるプラットフォーム向けのプログラムを生成するためのツール。例えばWindows上でLinux向けのアプリケーションを作成する場合に使用する。
- **ゲスト**: システムやサービスにおいて、一時的に利用するユーザーのこと。
- **原始プログラム**: プログラミング言語を用いて書かれた人間が理解できる形式のコード。コンピュータが直接実行することはできないが、コンパイラやインタプリタによって機械語に変換される。
- **コマンドインタプリタ**: ユーザーからの入力を解釈し、オペレーティングシステムに指示を伝える役割を持つソフトウェア。一般的にはシェルとして知られる。
- **コンパイラ**: 高水準プログラミング言語で書かれたプログラムを、コンピュータが理解できる機械語に翻訳するソフトウェア。／ 補足(saycon): 高水準プログラミング言語で書かれたコードを機械語に変換するソフトウェア。
- **コンパクション**: 実記憶管理において、メモリ内の断片化を解消する手法。
- **サービスプログラム**: オペレーティングシステムの一部であり、特定の機能を提供するためのソフトウェア。ユーザーやアプリケーションがハードウェア資源を簡単に利用できるようになる。
- **シェル**: オペレーティングシステムとユーザーとの間をつなぐインターフェース。ユーザーがコンピュータに対して命令を入力し、それに対する操作を実行する役割を果たす。／ 補足(saycon): ユーザーとオペレーティングシステムの間でコマンドのやり取りを行うインターフェース。
- **システムソフトウェア**: コンピュータを動作させるために必要な基本的なソフトウェアであり、特にオペレーティングシステム（OS）がその代表例。
- **ジョブ管理**: コンピュータシステムにおいて、処理すべき仕事やタスクを効率的に管理するための手法。仕事のスケジュール設定や実行状況の監視、資源の配分などが含まれる。
- **ジョブスケジューラー**: コンピュータシステムにおいて、プログラムやタスクを実行する順序やタイミングを管理するソフトウェア。
- **シンボリックリンク**: ファイルシステムにおいて他のファイルやディレクトリへの参照（リンク）を示す特別なファイル。ある場所にあるファイルやディレクトリを別の場所から簡単にアクセスできるようにする。
- **スケジューリング**: コンピュータにおいて、複数のタスクやプロセスが効率的に実行されるように順序を決定し、資源（CPU、メモリなど）を適切に配分するプロセス。
- **スラッシング**: 仮想記憶管理において発生する現象の一つであり、システムが十分なメモリを確保できず、ページフォールトが頻繁に発生することを指す。
- **スレッド**: プログラムの中で実行される処理の最小単位。同時に複数の処理を行うために使用され、マルチタスク処理や並行処理において重要な役割を果たす。
- **スワップアウト**: 物理メモリが不足したときに、現在使用しているデータやプログラムを一時的にディスクに移動させるプロセス。
- **スワップイン**: 仮想記憶管理において、一時的に記憶装置に保存されていたプロセスやデータを主記憶（RAM）に戻す操作。
- **セグメントページング方式**: 仮想記憶管理の手法の一つで、プログラムやデータをセグメントと呼ばれる部品に分割し、それぞれのセグメントをページという固定長のブロックにさらに細分化する。
- **セグメント方式**: 仮想記憶管理の手法の一つであり、プログラムやデータを意味的な単位で分割して管理する方法。
- **ソースライブラリ**: ソフトウェアの開発において再利用可能なコードの集まり。開発者は、このライブラリを使うことで、基本的な機能を自分でゼロから作成する手間を省くことができる。
- **タイムクウォンタム**: コンピュータが複数のプログラムを同時に実行する際に、それぞれのプログラムに割り当てられる時間のこと。
- **タイムスライス方式**: コンピュータが複数のプログラムを同時に実行するためのスケジューリング手法の一つ。各プログラムに一定の時間（タイムスライス）が割り当てられる。
- **多重プログラミング**: 複数のプログラムを同時に実行するための技術であり、主にOSの機能の一つ。
- **ディスパッチ**: 複数の処理やタスクを効率的に管理し、適切な順番で実行するための仕組み。
- **動的アクセス**: データの格納場所や参照方法が状況に応じて変化するデータ管理手法。特にファイルシステムやデータベースにおけるデータ取得において用いられる。
- **ノンプリエンプティブ方式**: マルチプログラミングにおけるスケジューリングの一種で、実行中のプロセスを強制的に中断しない方式。
- **ブートストラップ**: オペレーティングシステムが起動する際に、その基本的な機能を準備するプロセス。コンピュータの電源を入れた後、最初に実行される一連の手続きを含む。／ 補足(marke-predict): コンピューターの電源が入ってから操作ができるようになるまでの一連の処理。
- **プリエンプティブ方式**: オペレーティングシステムにおいて、実行中のタスクを強制的に停止させ、他のタスクにCPUの制御を渡す手法。／ 補足(marke-predict): マルチタスクOSが複数タスクの重要度や緊急度に応じて処理を制御すること。
- **プリプロセッサ**: プログラムがコンパイルされる前に、ソースコードに対して特定の処理を行うツール。主に、マクロの展開や条件付きコンパイル、ファイルのインクルードなどを行う。
- **プロセス**: コンピュータ内で実行されるプログラムのことを指し、その中にはタスクや状態遷移が含まれている。
- **ページフォールト**: コンピュータが仮想記憶管理を行う際に、必要なデータが主記憶（RAM）に存在しない場合に発生する現象。
- **マイクロカーネル**: オペレーティングシステムの基本的な機能を最小限に抑え、システムの運用効率を高めるためのアーキテクチャ。
- **マスタスケジューラー**: ジョブ管理においてタスクや処理の実行順序を決定する役割を果たすプログラムやシステム。
- **マルチブート**: 一台のコンピュータに複数のオペレーティングシステムをインストールし、起動時にどのOSを使用するか選択できる機能。
- **ミドルウェア**: 異なるソフトウェアやアプリケーション同士の橋渡しを行う、中間的なソフトウェア層。データベース、OS、アプリケーションの間で情報をやり取りしやすくする役割を持つ。／ 補足(saycon): オペレーティングシステムとアプリケーションソフトウェアの間で動作するソフトウェア。
- **モノリシックカーネル**: オペレーティングシステムのカーネルが一つの大きなプログラムとして構成されている方式。すべての基本機能が同一のアドレス空間内で動作する。
- **ユーザーモード**: オペレーティングシステムにおける実行モードの一つ。このモードでは、アプリケーションプログラムが限られたリソースや機能にアクセスすることができる。
- **リアルタイムOS**: 特定の時間制約の下で機能するように設計されたオペレーティングシステム。データの処理や反応に対して厳格な時間制限が要求されるアプリケーションで広く利用される。
- **ルートディレクトリ**: コンピュータのファイルシステムにおける最上位のディレクトリであり、すべてのファイルやフォルダがこのディレクトリの下に階層的に配置される構造を持つ。
- **ロールアウト**: 特定のソフトウェアやシステムのアップデート、機能追加の際に、それを段階的にユーザーに展開するプロセス。
- **ロールイン**: 実記憶管理において、必要なデータやプログラムを主記憶から補助記憶に移行し、再び主記憶に読み込む過程。
