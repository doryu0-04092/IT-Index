# 分類の食い違い・説明内容の食い違い 一覧（要確認）

fe-siken.com（および補足のsaycon/marke-predict）を分野別に収集する過程で気づいた、①こちらの`field`分類とfe-siken側の分類が食い違うケース、②複数ソース間で説明の**意味そのもの**が食い違うケースをまとめたもの。**terms.jsonのfieldや語義は書き換えていない。** 判断は本人が行う。

---

## 1. 分類の食い違い（fieldの割り当てが、fe-siken側の章立てと異なる語）

### 1-1. カテゴリ丸ごとの食い違い（最重要）

**fe-sikenのカテゴリ6「ハードウェア」は、こちらの「ハードウェア」分野とほぼ別物。** fe-siken側は論理回路・制御理論（AND/OR/NOT回路、フリップフロップ、真理値表、PWM制御、ダイオード、トランジスタ、IC/LSI/FPGA等、22語）だけを扱っており、こちらの「ハードウェア」分野（138語：プリンター、HDD、USB、HDMI、センサー、ICカード等の周辺機器・記憶装置）とは扱う内容がほぼ完全に別物。直接一致する語がほとんど無いため、この分野は参考情報が薄い状態になっている（詳細: `ハードウェア.md`）。

**アジャイル／開発プロセス系の語のまとまりが、分類先ごと違う。** こちらは「ウォーターフォールモデル・アジャイル・DevOps・XP・スクラム・テスト駆動開発・リファクタリング・スプリント・継続的インテグレーション・CMMI・DFD」等を「システム開発技術」に分類しているが、fe-sikenはこれらをまとめて「ソフトウェア開発管理技術」（カテゴリ13）に分類している。個別語の誤りというより、シラバスの捉え方そのものが違う可能性がある。

**技術戦略マネジメント関連語のまとまり。** 「価値創出の3要素」「キャズム（理論）」「リーンスタートアップ」「ベンチャーキャピタル（VC）」「CVC」をこちらは「経営戦略マネジメント」に分類しているが、fe-sikenは「技術戦略マネジメント」（技術経営=MOTの文脈）にまとめて分類している。

## 2. 説明の「意味」が食い違う語（言い回しではなく内容が違うもの）

- **FIFO**: marke-predictの説明はOSのページ置換アルゴリズムの意味。terms.json内での並び（LIFOと隣接）から見ると、データ構造（キュー）の原則を指している可能性が高い。同じ略語で指す対象が異なる。
- **PROM／EEPROM／EPROM**: fe-sikenの「ROM」一般説明（書き込み不可・不揮発性）と、marke-predictの「PROM」説明（電気的に書換え可能）が矛盾。両者は別概念（読み出し専用ROM と 書換え可能なPROM）であり、混同に注意。
- **CIM**: fe-sikenの説明はCommon Information Model（ネットワーク管理の概念）になっているが、掲載文脈（エンジニアリングシステム）から見て本来はComputer Integrated Manufacturing（コンピュータ統合生産）を意図していると考えられる。fe-siken側の説明取り違えの可能性。
- **EMS**: fe-sikenの説明はEnergy Management System（エネルギー管理システム）。terms.jsonの並び（FMC・FMS・MRP等の生産関連語と隣接）から見て、本来はElectronics Manufacturing Service（電子機器受託生産）を意図している可能性が高い。marke-predictは後者の意味で説明しており、fe-sikenと食い違う。
- **ラグ／リード**（プロジェクトマネジメント）: fe-sikenの説明はどちらも同音異義語（ネットワークの遅延／営業の見込み客）になっており、PMBOKのスケジュール用語（後続作業の猶予期間／前倒しできる期間）とは意味が異なる。fe-siken側のAI自動生成の取り違えの可能性が高い。
- **BSDL**（ハードウェア）: fe-sikenはOSSライセンスの節に掲載しているが、説明文はBoundary Scan Description Language（集積回路テスト用言語）の内容。BSDライセンスとの混同の可能性が高い。terms.json側の「BSDL」は後者（テスト用言語）の意味と解釈できるが、fe-siken自身の分類とは矛盾する。

## 3. fe-siken抽出内容が用語の一般的定義と大きく異なるように見える語（要目視確認・採用注意）

以下はfe-sikenページの自動生成説明が、試験用語としての一般的な意味とは別の同音異義語の説明になっている疑いがあるもの。次工程でそのまま参考にしないよう注意。

- **調歩同期**: 取得内容は「音声と映像のリップシンク」の説明。本来は非同期式シリアル通信の同期方式のはず。
- **キャラクター同期**: 取得内容は「キャラクター（登場人物）の動きの同期」の説明。本来は文字単位のデータ同期方式のはず。
- **ストップワードビット**: 取得内容は「特定のデータを無視するためのビット」。本来は非同期通信の「ストップビット」の可能性。
- **プッシュ**: 取得内容は「プッシュ通知」の説明。terms.json上は恐らくスタック操作（データを積む）の意味。
- **ノード**（saycon経由）: 「ネットワーク上のデバイス」の意味で取得。terms.json上は木構造・グラフの「節」の可能性。

## 4. 表記ゆれ・名称の新旧（食い違いというより確認事項）

- 「回線配置利用権」（terms.json）と「回路配置利用権」（fe-siken）: 集積回路レイアウトの権利。どちらかが誤記の可能性。
- 「下請法」（terms.json）と「中小受託取引適正化法」（fe-siken）: 2024年法改正で名称変更。terms.jsonが旧称。
- 「特定個人情報の適切な取扱いに関するガイドライン」（terms.json）と「…の適正な取扱いに関するガイドライン」（fe-siken）: 「適切」と「適正」で一文字違い。
- 「支払用カード電磁的記録不正作出罪」（terms.json）と「…不正作出等罪」（fe-siken）: 「等」の有無。

## 5. terms.jsonのセキュリティ分野に抜けている可能性がある基本語

fe-sikenはCIA triad（機密性・完全性・可用性）を並べて説明しているが、terms.jsonのセキュリティ分野には「可用性」「信頼性」の単独項目が見当たらない（グループC担当agentの指摘）。
